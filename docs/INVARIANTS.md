# Invariants

Non-obvious rules and constraints that are easy to violate by accident. This
is deliberately curated, not exhaustive — things the code already makes
obvious on read don't need to be here. If you change something on this list,
update it in the same commit; a stale invariants doc is worse than none.

## Game rules (domain)

- **Game codes are always exactly 6 uppercase alphanumeric characters** —
  generated by `_generate_code()` in `game_service.py`. Enforced server-side
  via `Path(min_length=6, max_length=6)` on every `{code}` route
  (`routes/games.py`), and client-side via `maxlength="6"`.
- **Nicknames are 1–15 characters.** Enforced server-side via Pydantic
  `Field(min_length=1, max_length=15)` on `CreateGameRequest`/
  `JoinGameRequest`, and client-side via `maxlength="15"`. Keep both in sync
  if this ever changes — the client limit is only a UX hint, not security.
- **Overtime: 3 grants, then forfeit.** Each overspend costs −10 points and
  resets the bank to 60s; the 4th overspend ends the game immediately. Rule
  lives in `game_engine/turn.py::apply_elapsed` — it's the single source of
  truth, don't duplicate the "3" or "60" anywhere else.
- **Elapsed time is charged before the move is judged**, in
  `Turn.apply()` — a rejected move still costs the real time spent
  attempting it. `NOT_YOUR_TURN` / `NOT_PLAYING` are the only two errors
  that bypass this, because they're rejected before the current player is
  even confirmed.
- **Winner determination differs by end reason**: forfeit/timeout →
  opponent wins outright regardless of score; a normal end (bag emptied, or
  six consecutive passes) → highest score wins. See `winner` computed in
  `GameView.vue`.
- **Six-pass rule requires six *consecutive* passes.** Any placement or
  swap resets the counter to 0 — passing once is never by itself risky.
- **The bag has exactly 2 blank tiles**, worth 0 points, playable as any
  letter. Not a bug if you see two "?" tiles in the same game.
- **Bingo bonus is +50**, for placing all 7 rack tiles in a single turn.

## Backend

- **Re-anchor the turn clock, never `clear()` it, after a move attempt** —
  including rejected ones. `turn_clock.clock.clear(code)` removes the
  `_turn_started_at` entry entirely, and `elapsed()` silently falls back to
  ~0 forever until something calls `mark_turn_started()` again. This was
  the root cause of a real "clock jumps back up" bug — always re-anchor.
- **Rejected-move feedback stays private to the mover.** Don't broadcast
  invalid-word/invalid-placement details (or a generic "opponent made an
  invalid move" notice) to the opponent — a move that never happened isn't
  their business.
- **The four backend "seams" own one thing each — don't reintroduce ad hoc
  duplicates elsewhere:**
  - `game_manager.py` — per-game locks + turn timers
  - `connection_lifecycle.py` — SSE connect/disconnect, pause/resume/forfeit
    state machine
  - `turn_clock.py` — elapsed-time measurement + overtime math
  - `game_broadcaster.py` — serializes `GameState` per viewer and pumps SSE
    payloads (this collapsed 4 previously-duplicated broadcast loops)
- **`crypto.randomUUID()` and `navigator.clipboard` both require a secure
  context** (HTTPS, or literally the hostname `localhost`) — both are
  `undefined` over plain HTTP / a LAN IP (e.g. testing on a phone via
  hotspot). `addToast()` used to call `crypto.randomUUID()` for toast IDs;
  when it threw, it silently aborted `updateLocalState()` mid-function
  (the `game.value = payload` assignment never ran), which looked like
  notifications *and* game-state updates both randomly breaking. Use a
  plain `Date.now()+Math.random()` id instead, and feature-detect
  `navigator.clipboard` with an `execCommand('copy')` fallback.
- **The dev server hangs on reload, not crashes.** Editing a backend file
  while `uvicorn --reload` is running and there are open SSE connections
  (any tab with a game open) makes it hang on "Waiting for connections to
  close" instead of actually reloading — it just never responds again. If a
  request that used to work suddenly seems to hang forever, check this
  before assuming a code regression; kill and restart `make dev` from the
  repo root.

## Frontend / design system

- **Session lives in `localStorage`, shared per-origin across every tab of
  the same browser.** Testing two players locally requires two separate
  browser profiles (or one regular + one incognito window) — two tabs of
  one browser will silently collide.
- **Theming is CSS-custom-property based, keyed off `[data-theme="light"|
  "dark"]` in `lexi.css`** — not Tailwind's `dark:` variant, which isn't
  configured for attribute-based switching anywhere in this codebase. To
  add a themed value: define the token in both `[data-theme]` blocks in
  `lexi.css`, then map it in `style.css`'s `@theme inline` to get a
  Tailwind utility class. Don't reach for `dark:` prefixed classes.
- **`--color-primary` is generic UI chrome; it is not the same accent as
  the Lobby CTA or the board's active-tile/turn-indicator highlight.**
  Those use separate token families (`--color-cta-*`, `
  --color-active-highlight`) specifically so that restyling one doesn't
  silently repaint the other (e.g. the in-game SUBMIT button vs. the Lobby
  CREATE GAME button).
- **`GameBoard.vue`'s cell size is fluid** (`clamp()` off `100vw`), not a
  fixed pixel value — the formula already accounts for `GameView`'s
  padding, the board's own border/padding, and the 14 inter-cell grid gaps
  (see the comment above `--board-cell`). Don't hardcode board dimensions
  elsewhere; if the layout changes, the formula's constant needs updating,
  not a new hardcoded size.
- **`position: sticky` elements ignore an ancestor's padding.** Safe-area
  bottom padding for a sticky bar (e.g. the mobile action bar) has to live
  on the sticky element itself, not on a wrapper around it.
- **`lg:` (1024px) is the only breakpoint in this app.** Mobile/desktop
  layout switches all happen at that one boundary — don't introduce a
  second breakpoint (e.g. `md:`) for a related layout change, or some
  elements will be in a half-transitioned state in between.

## Testing / verification

- **Test counts as of this doc**: `packages/backend-api` 80/80,
  `packages/game-engine` 79/79. A sudden drop is a regression, not
  flakiness — investigate before re-running.
- **Browser automation tooling can be flaky** (resize/screenshot timeouts
  are a known failure mode in some sessions). When it fails, fall back to
  `preview_evaluate` computed-style checks, or point a tab at the machine's
  actual LAN IP to reproduce device-specific bugs (secure-context APIs in
  particular only fail over a real non-localhost origin).
