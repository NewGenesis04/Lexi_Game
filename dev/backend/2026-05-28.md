### What was built

This session completed the entire `backend-api` package, taking it from a scaffold of empty stubs to a runnable FastAPI application. Every component was implemented test-first.

**`GameRepo`** — `packages/backend-api/src/backend_api/repositories/game_repo.py`

The `GameRepo` class wraps an `aioredis.Redis` client and provides nine async methods covering three concerns: game persistence (`save_game`, `load_game`, `delete_game`), session persistence (`save_session`, `load_session`, `delete_session`), and active-game tracking (`register_active`, `deregister_active`, `active_codes`).

Serialisation is handled by `_to_json`, which combines `dataclasses.asdict()` with a custom `_EnumEncoder(json.JSONEncoder)` to convert `str`-based enums (`GamePhase`, `MoveType`, etc.) to their string values. Deserialisation is handled by a chain of module-level helpers: `_state_from_dict` calls `_player_from_dict` (which calls `_tile_from_dict`), and `_move_from_dict` (which calls `_placed_tile_from_dict`). Enum values are re-wrapped on the way back: e.g. `GamePhase(d["phase"])`.

Redis key layout: `game:{code}` for `GameState` JSON, `session:{token}` for `PlayerSession` JSON, and `active_games` (a Redis Set) for the set of live game codes.

Tested in `packages/backend-api/tests/test_game_repo.py` against `fakeredis.FakeAsyncRedis(decode_responses=True)`. 15 tests cover the full round-trip for all data types including board state (with lowercase-blank convention), move history, and the empty-set case for `active_codes`.

**`schemas.py`** — `packages/backend-api/src/backend_api/schemas.py`

Defines the Pydantic layer that sits at the HTTP boundary. Inbound models: `CreateGameRequest`, `JoinGameRequest`, `PlacedTileIn` (with a `to_domain()` method that returns a `PlacedTile`), `PlaceTilesRequest`, `SwapTilesRequest`. Move submission uses a Pydantic v2 discriminated union — `PlaceMoveRequest`, `SwapMoveRequest`, and `PassMoveRequest` are unified under the type alias `MoveRequest = Annotated[Union[...], Field(discriminator="type")]`, keyed on a `Literal["place" | "swap" | "pass"]` field.

Outbound models: `TileOut`, `PlacedTileOut`, `MoveOut`, `PlayerOut`, `GameStateOut`, `CreateGameOut`, `JoinGameOut`. Each carries a `from_domain` classmethod. The security-critical one is `PlayerOut.from_domain(player, *, is_self: bool)`: when `is_self=False` the rack is returned as an empty list, enforcing the anti-leak guarantee from both the HTTP response and SSE broadcast paths. `GameStateOut.from_domain` takes a `viewer_id: str` and propagates `is_self` per player. It also replaces the raw bag with `bag_size: int`, preventing clients from reconstructing the draw order.

Tested in `packages/backend-api/tests/test_schemas.py`. 3 tests cover the sanitisation boundary directly.

**`GameService`** — `packages/backend-api/src/backend_api/services/game_service.py`

The business logic layer. `GameService.__init__` takes a `GameRepo`. Seven public async methods:

- `create_game` — generates a 6-character alphanumeric code via `_generate_code()`, assigns a UUID player ID, calls `bag_module.build_bag()` and draws 7 tiles, constructs a `GameState` in `CREATED` phase, persists game and session, registers the code as active.
- `join_game` — validates `CREATED` phase and player count < 2, draws a second rack, transitions phase to `PLAYING`, persists, starts the time-bank task.
- `get_game` — read-only, no lock; returns `GameStateOut.from_domain(state, viewer_id=player_id)`.
- `place_tiles` — acquires the per-game `asyncio.Lock` via `game_manager.get_lock(code)`, calls `board_module.validate_placement`, then `board_module.apply_placement` and `board_module.formed_words` on the post-placement board, then `dict_module.is_valid_word` for each formed word. Scoring uses `scoring.score_placement` on the **pre**-placement board (so premium squares apply correctly to new tiles only). Removes placed tiles from the rack by matching on `Tile.letter`, draws replacements from the bag, resets `consecutive_passes` to zero, checks end conditions, advances turn.
- `swap_tiles` — extracts `Tile` objects from the rack by letter, calls `bag_module.exchange_tiles`, resets `consecutive_passes`, advances turn.
- `pass_turn` — increments `consecutive_passes`; if it reaches 6, sets `GamePhase.FINISHED`.
- `forfeit` — sets `GamePhase.FINISHED` unconditionally, records a `MoveType.FORFEIT` move.

Internal helpers: `_assert_turn` raises `403` if the wrong player acts and `400` if the game is not in `PLAYING` phase. `_check_end` returns `True` (and mutates state to `FINISHED`) when the bag is empty and the current player's rack is empty; it computes the end-of-game tile-penalty transfer to the emptying player. `_start_timer` calls `asyncio.create_task` (synchronously — no `await` needed) on `_time_bank_task`, then hands the task to `game_manager.set_timer`. `_time_bank_task` sleeps for `player.time_remaining_secs`, then acquires the lock, validates the game is still running and the correct player is still active, and applies an auto-forfeit. `_broadcast` queries `sse_manager.tokens_for_game`, loads the session for each token to retrieve `player_id`, builds a per-recipient sanitised JSON payload, and calls `sse_manager.broadcast`.

Tested in `packages/backend-api/tests/test_game_service.py`. 16 tests use a `FakeGameRepo` (an in-memory dict-based stub), with `backend_api.game_manager.set_timer`, `game_manager.remove_game`, and `backend_api.sse_manager.broadcast` patched out via `unittest.mock`. Game logic that depends on the engine (board validation, dictionary lookup, scoring) runs against the real engine modules.

**`routes/games.py`** — `packages/backend-api/src/backend_api/routes/games.py`

Thin HTTP wiring. Three dependency functions: `_get_repo` instantiates `GameRepo` from `request.app.state.redis`; `get_service` wraps it in `GameService`; `_require_session` reads the `Authorization: Bearer <token>` header, calls `repo.load_session`, and raises `401` if the session is not found.

Five route handlers: `create_game` (`POST /games`, 201), `join_game` (`POST /games/{code}/join`), `get_game` (`GET /games/{code}`), `submit_move` (`POST /games/{code}/moves`), `forfeit_game` (`POST /games/{code}/forfeit`). `submit_move` dispatches on the discriminated union type using `isinstance` checks against `PlaceMoveRequest` and `SwapMoveRequest`; the `pass` branch is the implicit fallthrough.

Tested in `packages/backend-api/tests/test_routes_games.py`. 10 tests use `httpx.AsyncClient` with `ASGITransport`. `get_service` is overridden with an `AsyncMock(spec=GameService)` and `_require_session` is overridden with a lambda returning a fixed `PlayerSession`. A separate `unauthed_client` fixture overrides `_require_session` with an async function that raises `HTTPException(401)` to verify protected endpoints.

**`routes/events.py`** — `packages/backend-api/src/backend_api/routes/events.py`

SSE endpoint at `GET /events?token=<token>`. Token is a query parameter rather than a header because the browser `EventSource` API cannot set custom headers.

`_require_session` reads `token` as a query parameter (distinct from the header-based version in `routes/games.py`) and raises `401` if no session is found. The route handler `sse_stream` returns a `StreamingResponse` with `media_type="text/event-stream"` and two additional headers: `Cache-Control: no-cache` and `X-Accel-Buffering: no` (the latter prevents nginx from buffering the stream).

The async generator `_event_generator` first loads the current game state and immediately yields it as the opening event — ensuring a reconnecting client receives the current state without an additional round-trip. It then calls `sse_manager.subscribe(code, token)` to obtain the player's `asyncio.Queue[str]`, and enters a loop that races two tasks with `asyncio.wait(..., return_when=FIRST_COMPLETED)`: `queue.get()` (data from a broadcast) and `request.is_disconnected()` (Starlette's ASGI-level disconnect signal). Pending tasks are cancelled and awaited to suppress `CancelledError`. On disconnect, the loop breaks. A `finally` block guarantees `sse_manager.unsubscribe(code, token)` is called regardless of how the generator exits.

Tested in `packages/backend-api/tests/test_routes_events.py`. 4 tests: 401 on invalid token, correct `Content-Type` header, initial event containing the game code, and `unsubscribe` called on stream close.

**`main.py`** — `packages/backend-api/src/backend_api/main.py`

Application entry point. `load_dotenv()` is called at module load. Two environment variables are consumed: `REDIS_URL` (default `redis://localhost:6379`) and `CORS_ORIGINS` (default `http://localhost:5173,http://127.0.0.1:5173`, comma-split into a list). The `lifespan` async context manager (FastAPI's modern startup/shutdown hook) creates the `aioredis` client at startup with `decode_responses=True` and stores it on `app.state.redis`; it closes the client with `aclose()` on shutdown. `CORSMiddleware` is registered before the routers. `env.example` was added at `packages/backend-api/env.example` as a reference for required environment variables.

### Decisions taken

**`dataclasses.asdict()` + custom JSON encoder for serialisation, not Pydantic**

The domain models in `game_engine.models` are Python dataclasses, not Pydantic models. `dataclasses.asdict()` recursively converts the entire object graph to plain dicts in one call. The only gap is enum handling — `str`-based enums serialise as their enum object rather than their string value, which JSON rejects. `_EnumEncoder` fills this gap. Manual `_*_from_dict` helpers handle deserialisation. The alternative — introducing Pydantic into the engine layer — was rejected to keep `game-engine` zero-dependency and fast.

**Per-recipient SSE broadcast, not a single shared payload**

`GameService._broadcast` builds a separate JSON string per connected player, calling `GameStateOut.from_domain(state, viewer_id=session.player_id)` for each. A single shared payload was not used because the opponent's rack must be stripped before each player's payload is constructed. Sharing a raw payload and stripping at delivery time would require a second deserialisation step and create a window for accidental leakage if the logic were ever moved.

**Discriminated union for move submission (`POST /games/{code}/moves`)**

The three move types — place, swap, and pass — are handled by a single endpoint rather than three separate routes (`/moves/place`, etc.). The architecture document (Q10) specifies a single `/moves` path. Pydantic v2's `Annotated[Union[...], Field(discriminator="type")]` resolves the type before the route handler runs, so `submit_move` receives a concrete typed object and dispatches with `isinstance`. The alternative of a flat model with optional fields and a manual validator was rejected as more error-prone and less self-documenting.

**`asyncio.wait` for SSE disconnect detection, not a polling timeout**

The initial implementation of `_event_generator` used `asyncio.wait_for(queue.get(), timeout=30.0)` and only checked `request.is_disconnected()` after each timeout expired. This caused test hangs: after a test client broke out of the SSE stream, the generator sat blocked for 30 seconds waiting for the next event before it could observe the disconnect. The fix races `queue.get()` and `request.is_disconnected()` using `asyncio.wait(..., return_when=FIRST_COMPLETED)`. Since Starlette's `is_disconnected()` is a coroutine that blocks on the ASGI receive channel until a disconnect message arrives (rather than polling), it resolves immediately when the client closes the connection, making the generator exit promptly.

**Auth token in query param for SSE, `Authorization` header for HTTP**

`_require_session` in `routes/games.py` reads an `Authorization: Bearer <token>` header. `_require_session` in `routes/events.py` reads a `token` query parameter. The difference is forced by the browser: the `EventSource` API does not support custom headers, so the only viable mechanism for passing credentials over a browser-initiated SSE connection is a query parameter.

**`_get_repo` as the injectable dependency for route tests**

Route tests override `_get_repo` (rather than `get_service` or `_require_session`) as their injection point in `test_routes_events.py`. This keeps the real `_require_session` logic active in tests, so authentication is not entirely bypassed — the fake repo simply returns or withholds the session as configured. In `test_routes_games.py`, by contrast, both `get_service` and `_require_session` are overridden, since those tests are concerned with HTTP contract verification rather than auth mechanics.

### Problems identified

**SSE generator hanging in tests — resolved**

*Problem:* The original `_event_generator` used `asyncio.wait_for(queue.get(), timeout=30.0)` and checked `request.is_disconnected()` only after the timeout. Tests that streamed one event and then closed the connection would hang for up to 30 seconds before the generator acknowledged the disconnect and unsubscribed.

*Location:* `packages/backend-api/src/backend_api/routes/events.py`, `_event_generator`.

*Resolution:* Replaced the timeout-then-poll pattern with `asyncio.wait({get_task, dc_task}, return_when=FIRST_COMPLETED)`. Both tasks are cancelled and awaited on exit to suppress `CancelledError`. The generator now exits within the same event loop tick as the ASGI disconnect message arrives. The fix is at lines 47–64 of `routes/events.py`.

**`_get_repo` and `get_service` declared `async def` unnecessarily — resolved**

*Problem:* Neither `_get_repo` nor `get_service` in `routes/games.py` or `routes/events.py` contains an `await` expression. They are declared `async def` for visual consistency with `_require_session`, but this adds a coroutine wrapper where a plain function would suffice. FastAPI handles both `def` and `async def` dependencies; sync dependencies run in a thread pool executor.

*Location:* `routes/games.py` lines 16–21, `routes/events.py` lines 18–19.

*Resolution:* Both functions changed to plain `def` in both files. No other code required updating — FastAPI's `Depends` machinery handles sync and async dependencies identically from the caller's perspective.

**`swap_tiles` does not validate minimum bag size — resolved**

*Problem:* Standard Scrabble rules prohibit swapping if the bag contains fewer tiles than the number being returned. `GameService.swap_tiles` called `bag_module.exchange_tiles` without first checking `len(state.bag) >= len(letters)`. If a player attempted to swap three tiles when only two remained in the bag, they would draw two tiles and silently lose the third.

*Location:* `packages/backend-api/src/backend_api/services/game_service.py`, `swap_tiles`.

*Resolution:* Added `if len(state.bag) < len(letters): raise HTTPException(status_code=422, detail="Not enough tiles in bag to swap")` immediately after the lock is acquired and before any rack manipulation. The check runs inside the lock so it reads the authoritative bag state. Covered by `test_swap_tiles_insufficient_bag_raises_422` in `packages/backend-api/tests/test_game_service.py`, which sets the bag to 2 tiles and attempts a 3-tile swap.
