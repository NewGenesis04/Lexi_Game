## 2026-05-31 — Time control reimplemented as real-time deduction with overtime; three latent bugs fixed; frontend clock made drift-proof

### What was built

**1. Timer semantics changed from per-turn countdown to real Scrabble clock deduction.**

The original timer design fired a single `asyncio.sleep(secs)` per turn and auto-forfeited the player when it expired. This did not match the behaviour of a real Scrabble clock, where each move deducts only the actual wall-clock time the player consumed, not the full allotment.

The replacement is three-pronged:

- **`_turn_started_at` tracking** in `packages/backend-api/src/backend_api/game_manager.py:8,33-42`. A new module-level dict `_turn_started_at: dict[str, float]` stores `time.monotonic()` whenever a turn begins. Three accessors are exposed: `set_turn_started(code)`, `get_elapsed(code)` (returns `monotonic() - stored`), and `clear_turn_started(code)`.

- **`_deduct_time()`** in `GameService` at `game_service.py:275-279`. Called from `place_tiles` (line 154), `swap_tiles` (line 191), and `pass_turn` (line 216). It reads `get_elapsed(code)` for the current game, clears the stamp, and subtracts the elapsed seconds from the active player's `time_remaining_secs`, flooring at zero: `player.time_remaining_secs = max(0.0, player.time_remaining_secs - elapsed)`.

- **`_start_timer()`** at `game_service.py:281-287`. Replaces the old timer start. After setting the player's remaining seconds (possibly reduced by `_deduct_time`), it records `set_turn_started(code)` and spawns a watchdog that fires after the player's **current** remaining time (not the original per-player budget). This watchdog is the `_time_bank_task`.

**2. Overtime system added to the domain model.**

The `Player` dataclass in `packages/game-engine/src/game_engine/models.py:55` gained an `overtime_count: int = 0` field.

`_time_bank_task` at `game_service.py:289-318` implements a two-strike overtime protocol:

- **First timeout** (`overtime_count == 0`, line 299): The player loses 10 points, their clock resets to 60 seconds, `overtime_count` is set to 1, and a new watchdog is spawned at 60s. The state is saved and broadcast before the new task is created.

- **Second timeout** (`overtime_count == 1`, line 310): The player's clock is set to 0.0, the game phase transitions to `FINISHED`, a `MoveType.FORFEIT` move is recorded, and the game is torn down via `game_manager.remove_game(code)`.

- **Guard clauses** (lines 293-296): If the game is no longer in `PLAYING` phase or the current player has changed since the task was created, the task exits without side effects.

Both the backing `state.broadcast` and `game_manager.set_timer` calls inside `_time_bank_task` were already covered by the existing `mock_side_effects` fixture (`test_game_service.py:68-76`), which patches `set_timer`, `cancel_timer`, `remove_game`, and `sse_manager.broadcast` for all service tests.

**3. Overtime field surfaced through the schema layer.**

`PlayerOut` at `packages/backend-api/src/backend_api/schemas.py:108` now includes `overtime_count: int`. `MoveOut.from_domain` at `schemas.py:91,99` was corrected to include the `letters` list — the previous version omitted `letters` from the returned dict, meaning SWAP moves were silently losing their letter data on the wire.

`_state_out()` in `packages/backend-api/tests/test_routes_games.py:33-34` was updated with `overtime_count=0` in both `PlayerOut` fixtures to match the new required field.

**4. Frontend clock made drift-proof using wall-clock delta.**

The interval ticker in `frontend/src/components/ui/PlayerPanel.vue:12-29` was rewritten. Previously it used a blind `displaySeconds.value--` each second, which would under-count elapsed time when `setInterval` callbacks were delayed by browser throttling or tab backgrounding.

The replacement stores the authoritative server value and a local timestamp on every SSE update (`serverBase` and `baseTimestamp` at lines 13-14, updated at lines 34-35). Each tick computes elapsed from the wall clock:

```typescript
const elapsed = (Date.now() - baseTimestamp) / 1000
displaySeconds.value = Math.max(0, Math.ceil(serverBase - elapsed))
```

This guarantees that even if the interval callback fires late, `elapsed` reflects the true wall-clock duration, so the displayed time always converges toward the server's authoritative value.

**5. Overtime visual indicators added to the frontend.**

- `PlayerPanel.vue:130` — an inline `OT` badge rendered in red (`#dc2626`) on a red background, shown conditionally with `v-if="player?.overtime_count && player.overtime_count > 0"`.
- `PlayerPanel.vue:132` — the clock text colour switches to `#dc2626` (red) when the player is in overtime.
- `frontend/src/stores/game.ts:26,46-55` — `updateLocalState` now tracks `previousOvertimeCounts` per player ID. When a player's `overtime_count` transitions from 0 to a positive value, a toast is appended: `"{player.nickname} ran out of time! −10 points. +60s overtime granted."`.

**6. Three latent bugs corrected.**

- **Rack validation in `place_tiles`** (`game_service.py:129-138`): The original tile-removal loop iterated over `placed` tiles and tried to `pop()` matching entries from a copy of the player's rack, but never validated that a match was actually found. If a player sent a placement containing a letter not in their rack, `pop()` would silently skip it (because the inner `for` loop would exhaust without finding a match and move on), and the tile would not be removed — a data-corruption vulnerability under a malicious or buggy client. Fixed by adding a `found` boolean per placed tile; if any tile has no matching rack letter after the full inner scan, a `422` is raised.

- **Join race** (`game_service.py:70`): `join_game` was the only mutating endpoint that did not acquire the per-game `asyncio.Lock`. Two simultaneous join requests for the same game code could both see `phase == CREATED`, both check `len(players) < 2`, and both append a player, producing a 3-player game state. Fixed by wrapping the entire handler body in `async with game_manager.get_lock(code)`.

- **CORS origin whitespace** (`main.py:17-22`): `os.getenv("CORS_ORIGINS").split(",")` produced origins like `" http://localhost:5173"` (leading space) when the env var contained spaces after commas. The FastAPI `CORSMiddleware` performs exact string matching on origins, so `" http://localhost:5173"` would not match a request from `http://localhost:5173`. Fixed by adding `s.strip()` inside the list comprehension.

### Decisions taken

**Decision 1: Real-time deduction (`monotonic() - stamp`) rather than pre-allocated per-turn budget.**

The original design set `time_remaining_secs` as a per-turn countdown: the server slept for the full player budget and forfeited on expiry. The problem is that this does not match Scrabble rules — a player who takes 3 seconds on a move should only lose 3 seconds, not their entire turn. The alternative considered was to keep the per-turn countdown but use a very large budget. Rejected because it would still be asymmetric: a fast player would never experience time pressure, and a slow player would always forfeit on their first timeout regardless of cumulative time used across the game. Using `time.monotonic()` stamps means the accumulated deduction across all turns of a player is bounded by their initial `time_per_player_secs`, matching standard Scrabble clock behaviour.

**Decision 2: Two-strike overtime (penalty + 60s, then forfeit) rather than instant forfeit.**

The alternative was a single strike: forfeit immediately when time runs out. The two-strike design was chosen because a single misclick, network hiccup, or real-world interruption should not end the game. The 10-point penalty and 60-second overtime window give the player a chance to recover while still creating meaningful pressure. The second strike is an unconditional forfeit with no further extension.

**Decision 3: Wall-clock delta in frontend rather than trusting `setInterval` cadence.**

The frontend clock ticker originally used `displaySeconds.value--` on a 1-second `setInterval`. This is the simplest possible approach and works correctly under ideal conditions. However, browser throttling of background tabs (Chrome limits `setInterval` to 1 tick per minute in hidden tabs) and general jitter in the event loop would cause the displayed time to diverge from actual wall-clock time. The alternative considered was to increase the tick frequency and use smaller decrements (e.g., 4 ticks at 250ms), but this only narrows the error window without eliminating it. Storing the server timestamp and computing elapsed on every tick makes the display agnostic to callback timing — a late callback produces a larger `elapsed` value, keeping the display correct.

### Problems identified

**Problem 1: `_time_bank_task` is an `async` method, triggering a `RuntimeWarning` in route tests.**

`AsyncMock(spec=GameService)` in `test_routes_games.py:48` introspects `GameService` and discovers the `_time_bank_task` coroutine. Python's `unittest.mock` eagerly creates a coroutine for it during class construction, logs a `RuntimeWarning` that it was never awaited. The warning appears once per test file run:

```
coroutine 'GameService._time_bank_task' was never awaited
```

*Location:* `packages/backend-api/tests/test_routes_games.py:48`, `AsyncMock(spec=GameService)`.

*Resolution:* The warning is benign. The route tests never call `_time_bank_task` — they don't exercise the timer path at all. The mock discards the coroutine. Fixing it would require excluding `_time_bank_task` from the mock spec or suppressing the warning, neither of which improves coverage. *Open.*

**Problem 2: No integration tests for the timeout/overtime path.**

The seven new service-level tests (`test_game_service.py:267-353`) cover the `_deduct_time` and `_time_bank_task` methods directly by calling `svc.place_tiles` with patched `get_elapsed` and `svc._time_bank_task` directly with minimal sleep values. However, there is no test that wires the full route stack together with a fake clock and exercises the timeout through the HTTP boundary. The route tests (`test_routes_games.py`) use `AsyncMock(spec=GameService)` which bypasses all real logic. This means a future refactor that breaks timer wiring between the route layer and the service layer would not be caught. *Open.*
